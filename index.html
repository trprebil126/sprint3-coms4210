Key Differences & Mechanics

1. Target Security Property & Attacker Goal

AC attacks go after availability — the attacker wants to make the system slow or unresponsive for everyone. Side-channel attacks go after confidentiality — the attacker wants to quietly learn secrets without breaking anything.

2. Intended Logic vs. Unintended Side-Effects

AC attacks abuse the intended logic of the program itself: the code does exactly what it was written to do, just on an input that forces the worst-case running time. Side-channel attacks abuse unintended side-effects — the algorithm's outputs are never touched; instead the attacker observes how it runs (how long it takes, how much power it draws, what it does to the cache).

3. Attack Manifestation & Examples

AC example: crafting input that turns an O(n) linked-list traversal into an infinite loop (try the AC Simulator tab!). Side-channel example: measuring how long a password check takes to guess the password one character at a time (try the Side-Channel Simulator tab!).

The Defensive Intersection & Trade-Offs

Defenses for one class can open the door to the other. A timeout / resource limit is the standard AC fix — but a request that is abruptly cut off at a fixed time can itself become a timing signal an attacker measures. Conversely, making an operation constant-time to stop a timing side-channel means doing the worst-case work every time, which raises the baseline cost an AC attacker can amplify. Good designs budget for both: constant-time operations on secrets, plus input validation and resource caps on everything attacker-controlled.

🔥 AC Attack Simulator — the "static next" linked-list bug CWE-407

Based on a real class exercise. A catalog links 6 shapes into a list and getStats() traverses it with while(c != null) — an O(n) walk. But Rectangle stores its next pointer in a static field shared by all Rectangles. Place Rectangles so the shared pointer creates a cycle, and the "linear" traversal never ends — only a timeout guard saves it. That's an AC attack: a crafted input turns O(n) into O(∞).

🕵️ Side-Channel Simulator — timing attack on a password check CWE-208

A server checks a 4-digit PIN one character at a time and returns as soon as a character is wrong. That early-exit means a guess with more correct leading digits takes measurably longer. The PIN is never sent back — but the response time leaks it, digit by digit. Pick a secret PIN, then run the attacker and watch it recover your PIN using only timing.

_ _ _ _

What just happened?

For each position, the attacker tries every digit 0–9 and measures response time. The digit that took longest is the one that passed the comparison at that position — so the attacker locks it in and moves on. Instead of 10⁴ = 10,000 guesses, the PIN falls in at most 4 × 10 = 40 guesses. Turn on constant-time check and rerun: every guess takes the same time, the timing bars carry no signal, and the attacker's "best guess" is pure noise. That's the classic countermeasure — and the trade-off is that every check now costs the worst-case time.
